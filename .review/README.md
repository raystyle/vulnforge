# .review/ — 审查记录库

**定位**：独立审查代理（`/.claude/agents/reviewer.md`，代码+安全一体）的审查结论归档。每条审查一个单文件，进 git。

与相邻目录的分工：

| 目录                 | 回答的问题                               |
| -------------------- | ---------------------------------------- |
| `REVIEW.md`（仓根）  | 审查**规则**正本（从 main 读取，防自证） |
| `.review/`（本目录） | 每次**审查的结论与证据**                 |
| `.ad_records/`       | 需求决策与验收                           |
| `.research/`         | 先例研究与验证证据                       |

## 单文件格式（`NNNN-<scope>.md`，序号递增）

```markdown
# Review-NNNN | <审查范围一句话>

- 日期：YYYY-MM-DD
- 提交范围：<base>..<head>（或路径/PR）
- 审查代理：reviewer（新上下文）

## Blocking

- file:line — 问题 — 失败场景

## Report

- ...

## 安全面评估

- 不可信输入入口 / 命令执行点 / 密钥流向：列出及结论

## 修复与验证

- 逐条对应修复（commit 哈希）+ 复验结论

## 索引行回填

修完在本文件末尾追加"状态：已修复/部分/未修"，并同步 README 索引表。
```

## 维护规则

- 审查完成后立即落盘本目录（不再散落 result.md/对话）
- 修复后**回填**修复节——审查记录与修复形成闭环
- 索引表（下）随每次审查同步一行
