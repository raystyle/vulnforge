# adr — ADR 登记流程

## 步骤

1. **起草**：把用户需求整理为候选 ADR 单文件（四节格式见 `adr/README.md`），在对话中展示草案。需求措辞以用户原话为准，不自行引申。
2. **确认**：请用户确认草案（确认写入 / 修改后写入 / 先不写）。未确认不得写入文件。
3. **写入**：`adr/NNN-slug.md` 单文件 + 同步 `adr/README.md` 索引行。
4. **更新**：需求推进时只改对应单文件的"进度状态"节；交付时补"最终产物"节；验证后更新"是否满足需求"节并同步索引。

## 四节格式

```markdown
# ADR-NNN | 标题

- 日期：YYYY-MM-DD
- 状态：提案中 / 实施中 / 已完成 / 已废弃

## 需求

用户要什么，含子需求拆分

## 进度状态

各子需求当前状态 + 剩余待办（表格）

## 最终产物

交付资产清单：路径 + 一句话（表格）

## 是否满足需求

判定 + 证据
```

## 纪律

- ADR 不关心过程：研究经过、讨论历史、决策叙事不写进 ADR（留在 git 历史、memory 或 `.research/`）
- 序号递增，不重排不删除；被取代标"已废弃"并注明替代者
- 联动：需求落地为 rules/skills/CLAUDE.md 改动时，在"最终产物"节列明路径
- 决策固化进 docs/ 后，memory 只留指针
