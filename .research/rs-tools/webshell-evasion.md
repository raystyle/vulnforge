## 2. 检测面分类学（手册 §0.1——先懂查杀再免杀）

| 检测方式 | 机制 | 弱点 |
| -------- | ---- | ---- |
| 内容统计（传统） | 黑名单 + Hash 特征表 + 信息熵/特殊串频率 | 编码与字符串混淆即可绕 |
| 语义分析（AST） | 语法树追踪混淆变形 | PHP 动态特性吃力（可变变量/回调） |
| 机器学习（AI） | 样本特征库学习 | 组合爆炸超出训练分布 |
| 动态监控（RASP 沙箱） | Hook 危险函数实时阻断 | 成本高，部署少 |

→ 我们模板已按"密文通道"设计：静态扫描看到的是 base64 密文（内容统计无特征）+ 无 shell 函数字串（黑名单无命中）；RASP 面靠运行时加密流（行为层对抗，通道面已覆盖）。

## 3. 免杀手法原语（手册 §1-8 提炼——变异数据不是代码）

1. **编码绕过**：base64/ASCII(chr 拼接)/rot13——payload 不以明文出现
2. **字符串混淆**：自定义函数拼接（数组取模还原函数名）、文件名参与解码（读自身文件名提取密钥）、特殊字符串（换行/null 干扰正则）
3. **生成新文件绕过**：本体不执行命令，运行时 strtr 变换后写入第二阶段文件（两阶段：植入体是写入器，webshell 是产物）——**对应我们 WriteFile 投递形态的两阶段化**
4. **回调函数**：call_user_func_array/array_map——函数名不出现在调用位
5. **可变变量**：$$f 间接寻址
6. **数组/类绕过**：构造函数/析构藏逻辑
7. **嵌套运算**：多重运算符嵌套改变 AST 形态

**关键教训（手册 §0.3）**：`eval()` 是语言构造器非函数（不能可变函数调用）；PHP7+ `assert()` 同理——**最终执行位必须明文**，所以免杀混淆的是"如何到达执行位"而非执行位本身。我们模板的 XOR 解密循环 + `system` 位正是这个形态（解密在明文执行位之前）。

## 4. 落入 vf_rust_lib 的裁定

| 面 | 已有 | 吸收（mutate 数据面） |
| -- | ---- | --------------------- |
| 静态特征 | ✅ 密文通道（godzilla 形）：body/响应全密文 | mutate 原语集增 PHP 手册原语：编码轮换/字符串混淆/两阶段写入/回调包裹 |
| 生成变异 | 模板固定 | 生成时随机选原语组合（venom 思路：原语组合代数 → 每次生成不同变体） |
| 检测自测 | 无 | 手册 §0.4 检测平台清单进文档（长亭百川/阿里 TI/河马/D盾）——生成后自测流程记录 |
| 语言覆盖 | PHP/JSP | 手册 JSP/CSharp 册完善后跟进 |

- mutate 原语做成**数据**（JSON 原语表：type/参数/组合约束），不是代码——手册明确"手法会持续失效"（对抗性演进）
- 两阶段写入原语与 DeliverForm::WriteFile 天然组合：植入体=写入器，产物=加密通道 webshell
